### Sprint Review

- **What we demonstrated:**
  - Expanded backend regression tests for application validation, BR9, login limits, lock expiry and account access control.
  - Added boundary and negative-case tests for missing, null, malformed and out-of-range input values.
  - Added scoring regression tests for `rules-v1`, score boundaries, reason consistency, model versioning, seeded results and idempotency.
  - Verified rolling-hour scoring limits, exact time cutoffs and rejection behavior.
  - Expanded frontend tests for validation messages, focus management, ARIA attributes, responsive behavior and API error handling.
  - Added tests for scoring history persistence, date rendering, loading/empty/error states and refresh after scoring.
  - Added P0 browser workflow checks for creating, opening and scoring saved applications.
  - Added regression coverage for editing/cancelling applications, notifications, logout session revocation and private-response cache protection.
  - Enforced the test catalogue and pytest execution in CI. The final test suite passed with coverage above the required 90%.

- **Feedback received:**
  - Several edge cases were initially missing from the backend and frontend validation tests.
  - Exact error messages and boundary behavior needed to be aligned between the API, UI and tests.
  - Some workflows passed at unit/API level but still required browser-level verification.
  - Session revocation, notification persistence and scoring-history persistence required additional regression coverage.

- **Sprint outcome:**
  - Sprint 4 improved the reliability of the system primarily through broader automated and browser test coverage.
  - The main validation, scoring, authentication and P0 workflow regressions are now covered by tests and enforced through CI.
  - Remaining work should focus on maintaining the test catalogue and adding regression tests whenever new business rules or UI flows are introduced.
